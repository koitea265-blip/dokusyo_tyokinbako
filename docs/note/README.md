# note の紹介記事 — 入稿の手引き

連載「教室で使えるかもしれないもの作り」に載せる、
「どくしょ ちょきんばこ」の紹介記事一式です。

```
docs/note/
├── reading-books-note-article.md   記事本文。そのまま note に貼れます
├── images/                         実際にアプリを操作して撮った20点
└── README.md                       このファイル
```

---

## 1. 貼るまえに直すところ

### 連載番号

タイトルの `#◯` が埋まっていません。連載の #9 が Qalc の回だったことまでは
分かりましたが、それが直前の回かどうかを確かめられなかったので、
推測で埋めずに残してあります。ここだけ書きかえてください。

### カメラの画面の写真が1枚足りません

記事のいちばんの目玉はバーコードの読み取りですが、その画面だけは
入れられませんでした。撮影に使ったパソコンには本物のカメラがなく、
ブラウザが出す検査用の映像（緑色の模様）しか写らないためです。
作った映像をはめこむのは実物と食いちがうので、入れていません。

お手もとの端末で1枚だけ撮っていただけると記事が完成します。

1. 端末で https://reading-books.giga-school.com/ を開く
2. 「カメラで バーコードを よむ」を押す
3. 手もとの本のうら（978からはじまるバーコード）に枠を合わせる
4. 枠と「本の うらの 978 ではじまる バーコードに あわせてね」の行が
   写るように撮る

入れる場所は「📱 このアプリでできること」の、
「いちばん使ってほしいのはカメラです」の段落のすぐあとです。
キャプションの案は「本を20センチほど離して、まん中の枠に合わせるだけです。」

## 2. note に貼る手順

1. note で新しい記事を作る
2. `reading-books-note-article.md` の1行目（`#` の行）から `#` を外して、
   タイトル欄に貼る
3. 本文は `## 🏫 はじめに` から下を、そのまま本文欄に貼る。
   note のエディタは `##` を見出しとして受けとるので、目次が自動で作られます
4. 画像は note に貼りつかないので、`images/` の中身を1枚ずつ手で上げる。
   本文の `![…](images/01-home.png)` の行があった場所に置きかえる
5. 画像の直後にある一行の説明を、note のキャプション欄に移す。
   本文には残さない
6. ハッシュタグの案は
   `#GIGAスクール` `#小学校` `#読書` `#読書記録` `#ICT活用` `#教育アプリ` `#PWA`

太字も表も使っていないので、貼りかえのときに崩れるところはありません。

## 4. 記事に書いた数字の出どころ

| 記事の数字 | どこで確かめたか |
|---|---|
| 目標は1冊から99冊、はじめは10冊 | `index.html` の `#goal-input`（`min="1" max="99"`）と `js/app.js` の既定値 |
| スタンプの絵柄は12か月ぶん | `js/app.js` の `MONTH_STAMPS` を数えて12件 |
| 本の情報を6秒でうちきる | `js/app.js` の `setTimeout(stop, 6000)` |
| 調べにいくのは3か所 | `index.html` の CSP `connect-src` に openBD・Google Books・NDL の3つ |
| かならず要るのは題名とページ数の2つ | `js/app.js` の `saveBook()` が空で止めるのはこの2つだけ |
| 本を20センチから25センチ離す | `MANUAL.md` 4章 |
| 画面に出ている 38さつ / 2,884ページ / 49,090円 | 撮影用に入れた38冊の記録を、アプリ自身が集計した値 |

画面に写っている本の記録は、撮影のためにアプリの「じぶんで かいて きろくする」から
1冊ずつ手で入れたものです。実在する本の題名を使っていますが、
ページ数とねだんは記録の見た目をそろえるために入れた値なので、
実際の本の奥付とは合いません。記事の本文では、この数字を事実として扱っていません。

書誌検索（openBD・Google Books・国立国会図書館サーチ）は、撮影した環境から
外に出られなかったため、自動で本の情報が入るところは撮れていません。
記事でもその画面は使っていません。

## 5. 撮り直すときの手順

撮影の道具は `note-article` スキルのものを使いました。

```bash
npm i --no-save playwright
node <skill>/scripts/serve.mjs . 4180 /Reading-Books/     # 別のターミナルで
node <skill>/scripts/capture.mjs shots.mjs --base http://127.0.0.1:4180/Reading-Books/ --out shots
```

このアプリはビルドが要らないので、リポジトリの根元をそのまま配れば本番と同じです。
`/Reading-Books/` の下で配るのを省かないでください。
`manifest.json` の `scope` がこの絶対パスなので、根元で配ると挙動が変わります。

撮影用のシナリオは `.tmp-shots/` に置いて、納品前に消してあります。
中身は次の3つでした。

1. 38冊を「じぶんで かいて きろくする」から順に入れて、保存された中身を書き出す
2. 書き出した中身をブラウザに戻してから、画面を1つずつ撮る
3. 撮った画像の色数を落として `docs/note/images/` に置く

月をまたぐ記録は、スタンプの画面で年月をえらんでから入れています。
お祝いの画面（03）は、9冊入れた状態から10冊目を実際に記録して撮りました。

## 6. 文体について踏襲したこと

`references/style.md` のとおりにしています。

- 太字、斜体、表を使っていません。記号の `→` `／` `▲` `▶` `：` も0件です
- 箇条書きは手順のところだけです
- 専門用語を日常の言葉に置きかえました。
  ローカルストレージは「その端末の中だけ」、PWA は「ホーム画面に追加」、
  Service Worker は「一度開いたあとはインターネットが切れていても起動します」
- 絵文字は見出しだけです
- 見出しは基本の6つに、💰 と 🏅 と 🖨️ を足しています。
  スタイルの指定は「多くて2本まで」ですが、印刷は先生に届けたい機能なので
  3本になりました。減らすなら 🖨️ を「✨ 導入のメリット」に畳むのが自然です
- 本文の字数は約7,300字です（画像の行をのぞいた数）
- 教室での出来事は実体験として書いていません。
  「こうなればいいと思って作りました」までにとどめてあります。
  実際に使ってみた場面は、書き手が足すところです

## 7. 撮影中に見つけて直した不具合

記事とは別のコミットに分けてあります。**記事を出す前に、こちらを先に反映してください。**

BarcodeDetector を持たない端末（iPad と iPhone の Safari など）で
「カメラで バーコードを よむ」を押すと、画面が
「カメラの じゅんびを しています…」から先に進まず、カメラが開きませんでした。

読み取りを助ける QuaggaJS が、処理を分ける先を `blob:` から作ろうとして、
CSP の `worker-src 'self'`（とそのもとの `default-src 'self'`）にはじかれ、
準備の終わりが返ってこなくなっていたためです。エラーの表示も出ないので、
子どもからは「ずっと待たされる」ように見えます。

CSP をゆるめるのではなく、処理を分けずに本体と同じ場所で読み取る設定
（`numOfWorkers: 0`）に変えて直しました。実際に Chromium で確かめて、
カメラの枠と案内の行が出るところまで進むことを確認しています。

`APP_VERSION` は 2.5.0 から 2.5.1 に上げてあります。
